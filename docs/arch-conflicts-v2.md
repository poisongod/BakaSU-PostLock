# 架构冲突审计（对照 TrySU.md v2）

> **文档性质**：审计记录，不定义架构。标准一律以 [`TrySU.md`](../TrySU.md)（v2）
> 为准；证据行号以本文件提交时的代码为基准，重构后应回填勾销。
>
> **审计方法**：`src/`（驱动与提权链）与 `tools/` + 体系仓 `cli/manager` 两路
> 并行探查，逐条抽查行号核实。2026-11-13 首版。

## 0 结论摘要

当前实现与标准不是「若干功能未做」，而是**形态错配**：

> 现实现 = 提权链 + 共享内核 + 路径式入口 + 守护进程生命周期
> 标准要求 = 信任链 + 强虚拟化 + 能力式入口 + 可弃执行域

两者是换代关系，不是补丁关系。共 24 条冲突，收敛为 5 个架构级根因。

## 1 根因 A｜共享内核形态，隔离只是地址约定

违反：公理六/七/八、命题三 —— 按 v2 降格条款，全部降格为设计意图。

| # | 架构点 | 证据 | 冲突实质 |
|---|---|---|---|
| A1 | 跨世界操作靠直接物理内存读写，`is_direct_ptr` 只做页内地址检查 | `src/pipe.c:1453`、`src/root.c:1176` | 世界边界 = 同一内核里的地址约定，不是结构性不可达 |
| A2 | 在 VN 的 mount ns 里 `init_module`，模块进入共享内核 | `tools/postlock.sh:616-620`（自述 `namespace-agnostic`） | mount ns 边界在模块加载路径上完全不存在 |
| A3 | mount ns 隔离被当作「结构性隔离」验收 PASS | `tools/suvtz/scan.sh:476-478`、`tools/postlock.sh:373-380` | 判据与 v2 降格条款自相矛盾 |

## 2 根因 B｜无可信启动链

违反：公理十一（连带公理五～八不成立）。

| # | 架构点 | 证据 | 冲突实质 |
|---|---|---|---|
| B1 | W = 提权后热插入的未签名 LKM：先 patch `sig_enforce` 再 `finit_module` | `src/root.c:979-1012` | W 不是被验证出来的，是被塞进去的 |
| B2 | 完整性无构造时度量：blob 无条件覆盖、仅 `boot_id` 字符串比较 | `src/preload.c:176-226`、`src/main.c:278-288` | 「构造时哈希度量」这一半不存在 |

**边界说明**：B1 在本环境（CVE 提权路径）**无解**——没有厂商签名链可依。
按公理十一，隔离命题在本机永远不成立，文档应如实降级表述，不以功能补齐掩盖。

## 3 根因 C｜W 没有独立身份与最小边界

违反：公理一/三/十二。

| # | 架构点 | 证据 | 冲突实质 |
|---|---|---|---|
| C1 | 提权者 = 仲裁者：调用进程 patch 自己成 uid0，再装 su/ksud | `src/main.c:533,535`（`ROOT_PATCH_SELF=1`）、`src/root.c:1470` | 主权与执行同体，权限归属无法分离 |
| C2 | restore（`u:r:kernel:s0`）当 W：数百行 shell 持全 caps + W 状态写权 | `tools/postlock.sh:298-1064` | 恢复者既非 N 也非 W；W 代码集远超三类 |
| C3 | `su_daemon` 常驻 uid0 按连接分发 root shell——主权落在 VN 用户态 | `src/su_daemon.c:381-419,708-741` | 授权与执行都在 VN 进程树内（v2 主权/执行二分直接命中） |
| C4 | W 可缺省：无 holder 只记 `WARN`，仍写 `POSTLOCK-RESTORE-OK` | `tools/postlock.sh:398-399,1062` | 主权唯一性被降为增强项 |
| C5 | 特权路径承担改标签/装 APK/清 PIN/导出 pstore 等业务 | `src/preload.c:154-174`、`src/util.c:1314-1358` | 14k 行 exploit 整体成为 TCB |

## 4 根因 D｜入口不是「能力」，是路径/设备/文件

违反：公理九/十。

| # | 架构点 | 证据 | 冲突实质 |
|---|---|---|---|
| D1 | 唯一入口 = 全局 `misc.fops` 劫持 `/dev/ashmem`，兜底 `chmod 0600` | `src/fops.c:45-49`、`src/main.c:318-334` | 任何进程可命中伪入口；缓解靠运行期权限 = 公理八排除的过滤 |
| D2 | 入口接受 VN 给定的任意内核地址 | `src/pipe.c:1453-1478` | 公理十要求不信任任何指针，这里全盘信任 |
| D3 | 准入判据 = VN 可写文件 `/data/local/tmp/su.allow`，缺失即放行 | `src/su_daemon.c:607-627`（`if (!f) return 1;`） | 主权判据放在被管理者可写处，且 fail-open |
| D4 | 入口无一次性能力：1 字节 mode + 持久连接，可无限重放 | `src/su_daemon.c:629-665` | 公理九的 nonce/超时/单调计数器完全不存在 |
| D5 | sidecar `0644` 路标，任何进程可读 pid 后自行 `setns` 进 VN | `tools/postlock.sh:508-510`、`TrySU/cli/src/main.zig:263-272` | N→VN 无仲裁、无能力；审计记录写在 VN 自己 tmpfs，写失败仅告警 |
| D6 | `--trysu-ns <pid>` 进任意 ns、`-M` 直达 init ns | `TrySU/cli/src/main.zig:553-559,619-657` | 目标世界由调用者 argv 决定，W 不参与 |
| D7 | su 落点由恢复流程覆盖 + sucompat 改写 + stat 门面 | `tools/postlock.sh:853-881,718-724` | 入口同一性靠 sha1/inode 巧合，不靠内核能力 |

## 5 根因 E｜生命周期错位

违反：命题五「执行可弃」、公理四、公理十二。

| # | 架构点 | 证据 | 冲突实质 |
|---|---|---|---|
| E1 | VN = 常驻 `pause()` 守护进程的 mount ns | `tools/wns/wns.c:114-128` | 「执行可弃」被实现为不可弃；进程死则 VN 无表示 |
| E2 | Phase C 删除 N 侧副本，VN 成为恢复材料唯一持有者 | `tools/postlock.sh:769-807`（自述「tmpfs dies with the holder」） | 「VN 可毁、N 可复」反转成「N 的复性依赖可毁侧」 |
| E3 | 恢复脚本/状态/度量信息落在 N 与 VN 可写路径 | `tools/postlock.sh:1066`、`src/root.c:1626-1652` | 恢复信任根落在被恢复对象上 |

## 7 v2 新条款「新暴露」的冲突

v2 更新把审计标准抬高了一档，四条新条款直接命中现实现：

1. **主权/执行二分** → 暴露 C3（`su_daemon` 在 VN 里持有主权性分发权）
2. **强虚拟化前提 + 降格条款** → 暴露 A3（mount ns 判据与标准自相矛盾）
3. **一次性能力 + nonce/单调计数器** → 暴露 D4（入口可重放）
4. **恢复信任根独立于可写状态** → 暴露 E2/E3（恢复材料与脚本都在可写侧）

## 8 处置优先级

| 序 | 动作 | 覆盖条目 | 成本 |
|---|---|---|---|
| 1 | **先删**：holder 守护、sidecar、Phase C 删 N 副本、「W 可缺省」放行 | E1/E2/D5/C4 | 低；删除后反而更接近标准 |
| 2 | **再换入口**：内核签发的单次能力 + 固定入口 + fail-closed | D1/D2/D3/D4/D6 | 中；这是 W 入口仲裁雏形 |
| 3 | **再补度量**：构造时哈希基线，判据从「ENOENT」升级为「度量相符」 | B2/A3 | 中 |
| 4 | **最终边界**：强虚拟化/硬件隔离域 | A1/A2 | 高 |
| — | **无解项**：可信启动链（B1）——本环境无签名链，公理十一如实降级 | B1 | — |
