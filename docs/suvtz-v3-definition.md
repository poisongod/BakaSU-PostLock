## 0. 术语与符号

| 符号 | 含义 |
|---|---|
| `N` | 默认世界（Normal World）：未 root 的 Android 用户态，以及内核中不涉及 root 的路径 |
| `W` | 特权执行世界（Secure World 的软件对应）：一组 (主体, 客体) 的集合 |
| `D` | 检测域，`D ⊆ N`：`N` 里真正会做检测的那部分（EL0 应用态，以及内核中向 EL0 输出观测值的路径） |
| `S` | 观测表面：`D` 可发起的系统调用 / API 调用及其返回值 |
| `Task` / `Inode` | Linux 任务与 inode（世界标记的载体） |
| `E` | 入口集：从 `N` 到 `W` 的全部合法转换 |
| `M` | 入口监控：`E` 上每条转换的准入判定 + 记录 |
| `Dev_stock` / `Dev_rooted` | 未 root 的设备状态 / 本项目的设备状态 |

`W` 的实例（当前设备）：`ksu` 域、`su` 通道、模块与隐藏策略、`W` 自己的文件树与挂载视图。

## 1. 定义

**定义 1（SUVTZ）。** SUVTZ 是一个四元组

```
SUVTZ = ( W , N , E , M )
```

并且它必须在以下五条上全部成立。**缺任何一条，该方案都不是 SUVTZ**（反例见 §5）。

| 条款 | 名称 | 内容 |
|---|---|---|
| **D1** | 双世界 | `W ≠ ∅` 且 `N \ W ≠ ∅`。`W` 与 `N` 是两个执行世界，不是同一世界里的两个权限等级 |
| **D2** | 世界标记 | 存在标记函数 `w : Task ∪ Inode → {W, N}`，且**只有 `W` 内的主体能写该标记** |
| **D3** | 隔离 | `∀ o ∈ W`，`path_N(o) = ⊥`——客体在 `N` 的命名空间中**没有路径**（不是"路径存在但被拒") |
| **D4** | 唯一入口 | `∀ 转换 t : N → W`，`t ∈ E`，且 `E` 可被穷举、每条各有**单一分发点 + 单一准入判定** |
| **D5** | 入口监控 | `∀ t ∈ E`，`M(t)` 在 `t` 生效**之前**被求值，且结果可记录、可离线核验 |

### 1.1 三条必须随定义一起读的限定

1. **D3 的 `⊥` 指 `ENOENT`，不是 `EACCES`。**
   `EACCES` = 对象存在、你看不到（过滤层）；`ENOENT` = 对象不存在（结构性隔离）。
   这是整份定义里唯一不可妥协的分界线，也是"出口过滤 vs 世界隔离"的可判定形式。
   推论：任何依赖"运行时判断调用者是谁"的隐藏，一律不满足 D3。

2. **D2 的标记是执行世界的归属，不是状态事实。**
   `w` 描述的是"这个 task/inode 属于哪个世界"，不是"这台设备现在有没有 root"。
   **标记被读到 ≠ 边界破了**，只等于"边界被观测到了一次"。把 `w` 当成"我的 root 状态"是设计跑偏的起点。

3. **D5 的"生效之前"是时序约束，不是日志约束。**
   事后打日志不等于监控。监控要求在动作产生效果之前求值，并且**拒绝必须能真正阻断该动作**。

## 2. 符合性判据

定义必须可判定，否则无法验收。每条给出判据与判定方法：

| 条款 | 判据 | 判定方法 |
|---|---|---|
| **D1** | `W` 至少有一个在 `N` 中不可达的实例；`N \ W` 非空（存在可证明不在 `W` 内的主体） | 两侧对照：`W` 侧看到对象、`N` 侧同名路径 `ENOENT` |
| **D2** | 标记写入者矩阵：`W` 内主体可写、`N` 内主体写入被拒（或标记对 `N` 只读） | 逐主体尝试写标记 + 读回；记录准入判定来源（SELinux 域 / uid / 允许表） |
| **D3** | `N` 侧路径解析返回 `ENOENT`，**且** `W` 侧同路径解析成功 | `mountpoint -q` / `stat` / `ls` 在两侧分别执行；错误码必须逐字记录（`ENOENT` vs `EACCES`） |
| **D4** | 入口清单可穷举，且**每个状态改变/读取动作都能归到清单中的某一条**；清单中每条只有一个分发点 | 反例搜索：新增一条从 `N` 到 `W` 的路径，看它是否落在 `E` 之外（落在外面即不满足） |
| **D5** | 每次跨界都产生一条**在动作生效前**求值的判定记录，且该记录能离线核验 | in-band 判据行（如 `suvtz-w: su-gate open/closed`）；不可伪造需要信任根（§3 的 T1a） |

**D4 是唯一无法靠枚举通过、只能靠反证维护的条款**：它要求证明"不存在第二个入口"，这是否定命题，只能靠持续的反例搜索来逼近。因此 **D4 的符合性是"未发现反例"，不是"已证明唯一"**——这一点必须写进定义，否则等于宣称不可证伪的能力。

## 3. 等级（信任根）

等级分的是**谁在背后强制**，不是实现手段，也不是代码量。同一个等级内部，隔离强度取决于实现层的选择（结构性隔离 / 过滤层 / 入口审计）。

| 级别 | 信任根 | 承诺 | 本设备可达性 |
|---|---|---|---|
| **T0** | 我们自己的内核代码（诚实假设：该代码可信） | `D` 无法区分 `Dev_rooted` 与 `Dev_stock` | ✅ 可达 |
| **T1a** | TEE KeyMint HMAC（密钥不可导出） | 即使内核**只读**被攻破，也无法伪造"用户授权过"或篡改隐藏策略 | ⚠️ 待三个前提实验 |
| **T1b** | 无 | — | ❌ 不可达（需要 EL3） |
| **T2** | EL3 / Secure-EL2 / TZASC / GIC 分组 | 硬件级不可达 | ❌ 不可达 |

T1b 不可达是**数学事实**而非实现不足：

```
Obs(W)     = 能观测 W 的实体集合
Trusted(W) = 可信实体集合
不可达性成立  ⟺  Obs(W) ⊆ Trusted(W)
```

- 硬件 TrustZone：`Obs(W) = {EL3}`，EL3 受信 → **成立**。
- 本设备：EL1 同特权级无 MMU 隔离，`Obs(W) ⊇ {我们的内核代码} ∪ {所有其他 EL1 代码}`。存在不可信 EL1 实体（`oplus_root_check_succ`、`oplus_exec_block`）→ `Obs(W) ⊄ Trusted(W)` → **严格意义的不可达为假**。

**因此 SUVTZ 的正确承诺对象是 `D`（`D ⊆ N`），不是"N 中所有特权级"。** 把"最高特权级"排除在外不是给命题加括号，而是在括号里承认命题为假；换坐标才是诚实的做法。

## 4. 承诺边界

| 面 | 能否承诺 | 理由 |
|---|---|---|
| 机密性（观测不到） | ✅ T0 范围内 | 等价性可枚举验证 |
| 完整性（改不了状态） | ✅ 标记只有 `W` 内主体能写 | 与 T1a 的 TEE 结论一致 |
| 可用性（影响不了） | ❌ | `N` 里的特权用户态可重启设备、杀进程、耗尽资源 |

以下四件事在本设备上**任何软件方案都做不到**，包括本定义下的 SUVTZ：

1. 对完全控制内核的对手（T1b）隐藏；
2. 保证可用性；
3. 对服务端证明（Play Integrity / SafetyNet / 银行风控）伪造；
4. 对物理 / 侧信道隐藏。

## 5. 非 SUVTZ 的反例

反例比定义更能确定边界。以下五种方案都很常见，**没有一种构成 SUVTZ**：

| 反例 | 实际是什么 | 违反 |
|---|---|---|
| `/proc/modules` 里把 `kernelsu` 行过滤掉 | 出口过滤 | **D3**：对象存在，只是输出被改写 |
| 改包名 / 改属性 / 改符号表 | 出口过滤 | **D3**：同上，且破坏 D2（标记仍在 `N` 内可推断） |
| 一个 `unshare -m` 沙箱，没有任何跨界协议 | 沙箱 | **D1/D4**：有隔离但没有"世界"，也没有入口 |
| 有 `su` socket，但另有 `debug su` 管道 / `reboot` magic / 参数写等多条独立路径 | 多入口后门 | **D4**：`E` 不可穷举，且每条各有自己的准入判定 |
| 入口有鉴权但只在事后打 `printk` | 后门 | **D5**：监控不在生效前求值，无法阻断 |

一个便于记忆的判定顺序：**先问 D3（是不是真的不存在），再问 D4（入口是不是一个），最后问 D5（入口是不是被看着）。** 三者顺序不能反——D5 做得再好，D3/D4 不成立时只是"把后门记录得很完整"。

## 6. 当前符合性状态（诚实标注，2026-11-11）

**本节是实现状态，不是定义的一部分。** 每轮验收后更新。

| 条款 | 状态 | 依据 |
|---|---|---|
| **D1** | ✅ 成立 | `W` 的独立 mount namespace 已接入 restore（`tools/wns` holder，boot `9101e66c` 端到端 `by=kernel`）；物料迁入 + `N` 侧副本删除已验收（boot `59eeb053`） |
| **D2** | ✅ 成立（范围有限） | `TIF_PROC_UMOUNTED`（per-task）、`AS_FLAGS_SUS_PATH` / `AS_FLAGS_SUS_MAP`（per-inode）；写入者只限 `ksu` 域。**范围有限**：`run-as`（`u:r:runas_app:s0`）结构性不带该标志，属承诺范围外 |
| **D3** | ✅ 成立（客体集小） | Phase C 后 `ocsk` / `postlock_adbkey.pub` / `pp_adb_tcp.bin` 的 `N` 与 `$TMP` 副本已删，`N` 侧 `n-side-absent stage=ENOENT`；`W` 侧 in-band `cksum` 逐字节校验通过 |
| **D4** | ❌ **不成立** | `E` 事实上不唯一：`sucompat` `execve` 改写、`ksud debug su` 管道、`libksud.so` 的 `reboot` magic、`ksu_debug_manager_appid` 参数写、SUSFS `reboot` 命令族各自独立，无统一分发点与准入表 |
| **D5** | ⚠️ 弱成立 | 已有 in-band 判据（`suvtz-w: su-gate open/closed`、`install fd for ksu manager`、`susfs:[uid][pid][func] CMD_... -> ret`），但只有 `printk` 级，不可离线核验、不可反抗否认 → 需 **T1a** 才补齐 |

**结论：当前实现是 `D1+D2+D3 成立、D4 不成立、D5 弱成立` 的部分 SUVTZ（T0 级）。**
按 §1 的严格口径，**D4 不成立即不构成完整 SUVTZ**——这是当前最欠的一层，比过滤层漏几个观测面更根本：过滤层的缺口是"看到了"，入口的缺口是"被用掉了"。

**下一步的唯一阻塞项 = D4**：入口收敛（协议入口 4 条 → 单一分发点 + 单一准入表）。D5 的提升依赖 T1a，不属 T0 范围。

## 附录：一句话版本

> **SUVTZ = (W, N, E, M)**：存在一个特权执行世界 `W`，它在默认世界 `N` 的命名空间里**没有路径**（`ENOENT` 而非 `EACCES`）；`N` 只能通过**一个可穷举的、在生效前被求值与记录的**入口集 `E` 请求服务、不能读取状态；世界标记 `w` 只有 `W` 内主体能写；强度等级由信任根决定（本设备上限 T0 / T1a）。**D1~D5 缺一不成立；当前 D4 不成立，故当前只是部分 SUVTZ。**
